## 二、评估结论

### 2.1 速度与成本（09-28/29，384 条真实新闻）

| 轨道 | 总耗时 | 吞吐 | 单条 p50 | 成本/384 条 |
|------|--------|------|---------|------------|
| Jev 并发 16 | **12.0s** | 32.0 条/s | 0.28s | $0.018（token 口径）/ $0.0094（决策牌价） |
| Jev 并发 8 | **23.6s** | 16.3 条/s | 0.27s | 同上 |
| 宣传口径 | 24.9s | 15.4 条/s | — | $0.19 |
| DeepSeek Flash（8 并发） | 146.7s | 2.6 条/s | 1.9s | ≈$0.035 |
| DeepSeek Pro（8 并发） | 1487.6s | 0.26 条/s | 25.1s | ≈$0.37~1.49 |
| Jev 串行（现 jev_client 形态） | 2.5~13 min | 0.5~2.6 条/s | 0.28s | 同并发 |

三个必须写进采纳决策的前提：① 提速靠**并发改造**，不靠模型本身；② 必须带**重试**（上游 503 时变）；③ 决策模型只答题不解释——省 token 的原因也是它不能替代 LLM 写摘要的原因。

### 2.2 质量判定（09-29，84 条人工 gold 终审）

**内容强度**（gold 分布 {3:0, 2:18, 1:22, 0:44}——语料真实分布底重型，无一真里程碑）：

| 判定器 | 完全命中 | ±1 命中 | 偏差 | 序相关 | 终局定位 |
|--------|---------|---------|------|--------|---------|
| kw | 42.2% | 79.5% | +0.11 | 0.239 | **主流程维持**（底部堆积不冤；错误在 13 条假里程碑——政策/金融 30 档词过松，属标尺问题） |
| Jev（C 问法） | 45.8% | 83.1% | -0.37 | 0.086 | 影子观察中；切换排在七细类之后 |
| DeepSeek Pro | 56.6% | 84.3% | -0.40 | 0.276 | **参照轨**（最优但低估中间档、慢 25s/条、贵 20~160×、有 >12h 故障史） |

**七细类（choice，Jev 设计强项）**：Jev **59.0%** vs kw **45.8%**——P3 ① 切换的黄金依据。全库影子侧同向：kw 系统性把政策法规判少、企业经营判多（gold 与 600 条/轮影子双证据）。

**三次独立验证守住同一条红线**：Jev 的 score 绝对刻度形态（A）在 P0、预登记、生产影子三处全部 ≥90% 挤最高两档——「强度不交给 Jev」不是一次实验的结论，是可复现的系统属性。

### 2.3 判定器终局定位

| 判定器 | 角色 | 一句话 |
|--------|------|--------|
| 关键词 | 现行主流程 | 可解释、零成本、零依赖；强度底重不冤，顶档虚高等标尺校准 |
| Jev | 七细类切换候选 + 相关性门控候选 | choice/noul 问法强项；$0.000038/条、0.27s、复跑漂移 <1pp |
| DeepSeek Pro | 参照轨（kw/Jev 分歧仲裁） | 强度最优但慢贵不稳；Pro 故障自动回落 Flash |
| DeepSeek Flash | 回落轨 | 已知系统性偏低，优于空 |

## 三、生产架构（现状）

```
服务器 systemd timer（每 30 分钟）
  └─ green-policy-sync.sh → update_news.py --obsidian-dir . --window-hours 96
       └─ 尾部 _run_jev_shadow()（score 铁律不变，只写影子字段）
            ├─ native 直连 api.typesafe.ai/v1/systemone
            │    key=项目专用（指纹 0cd588a160ae，/etc/green-policy.env，600 权限）
            │    model=jev-1.13.0（钉版本，jev-latest 解析实证）
            ├─ 8 问/条：sub_dim(choice) + is_green/is_noise(noul) + 强度 A(score) + C(3×noul) + topic
            ├─ 护栏① cap 600/轮 ② budget 180s 墙钟 ③ interval 60min 门控
            ├─ 护栏④ 去重：data/jev-shadow-seen.json（id→{ts,shadow}，7 天裁剪，
            │    跳过周期只读+回填字段——记忆不放会被重写的文件里）
            └─ 产出：rec["jev_shadow"]（latest-24h*./history 沉淀）+ jev-shadow-report.json（每轮覆盖）
```

影子侧持续产出的三个观测（10-05~08 累积）：细类一致 ~41-44%（分歧即 kw 待修清单）；强度 ±1 ~91%；**is_noise≥0.5 占 36.2%**——语料质量治理的自动证据清单（颁奖/揭幕/招募/通讯类混入）。

## 四、踩坑与修复记录（按时间）

| # | 坑 | 修复 | 教训 |
|---|----|------|------|
| 1 | TypeSafe 上游 503 风暴 + 延迟劣化 5 倍（09-28） | `jev_client` 快速失败类重试 ×2（0.8s 退避）、慢超时不重试、熔断按逻辑调用计 | 上游时变是常态，重试+熔断是接入前提 |
| 2 | SF V4-Pro 端点持续故障 >12h（09-28~29） | `score_diff_monitor` Pro→Flash 自动回落（记录 `fallback_to_flash` 不静默混轨） | 双轨依赖单一端点会整轨断；**预登记期数据要健康检查**——故障期跑分差点把 Pro 误判成"塌陷不采用" |
| 3 | 影子去重失效：记忆存在被周期性重写的文件里（10-08，自己埋的） | 独立 `jev-shadow-seen.json` + 跳过周期字段回填；本地三周期场景测试后才部署 | **跨周期记忆必须放只有自己写的文件**；"首个生产周期验证过"不等于逻辑对（22:02 那轮恰逢旧文件残留而侥幸通过） |
| 4 | 部署时机坑：scp 落在抓取运行期（10-08 亲历） | 等 `systemctl is-active` = inactive 再传（运维文档既有纪律） | 模块启动即载入，运行中替换代码不生效 |
| 5 | 后台任务跨夜挂起污染 wall-clock（serial 轨 68717s 假数据） | 弃 wall 用逐条延迟分布；长任务预期跨夜时不用 wall 下结论 | Windows 睡眠会让 monotonic 跨夜跳动 |
| 6 | Git Bash MSYS 把 `export JEV_PATH=/v1/...` 转成 Windows 路径 | env 全在 Python 内 `os.environ` 赋值 | 本机 Git Bash 跑 API 测试的固定坑 |

方法学沉淀三条：**预登记防偏置**（预测冻结在标注前，漂移 <1pp 还顺带验证了判定稳定性）；**AI 初审只作信号不作依据**（38 条分歧归因方向被 gold 证实，但结论权始终在人工 gold）；**一致率 ≠ 准确率**（两把未标定的尺子互量无意义——P0 最大收获，gold set 因此而生）。
