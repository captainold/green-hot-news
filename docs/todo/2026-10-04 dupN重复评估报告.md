## 一、结论先行

**这 1039 组不是"标题巧合"，而是同一篇文章存了两条 url**：一条是**站点直连 url**（正文抓不到，`## 正文` 为空），一条是 **Google News 聚合 url**（正文抓到了）。

- 同 base 组的 url 形态：**`direct + gnews` 934 组（90%）**、`gnews` only 63 组、`direct` only 33 组
- **解码验证（决定性证据）**：把 gnews 那条的 url 用 `article_content._decode_google_news_url` 解码，**10/10 与同组直连 url 逐字符相等**
  （样本：`ww2.arb.ca.gov/...heavy-duty-greenhouse-gas-certification-program`、`www.energy.gov/articles/energy-secretary-acts-protect-mid-atlantic-grid`、`afdc.energy.gov/vehicles/search/?page=26` …）
- 全库 `id` 撞车 **0 个** → 命名与 id 体系没坏，坏的是**入库时的 url 级去重**（`export_qmd` 的 url 索引只认原始 url，认不出聚合 url 与直连 url 是同一篇）

## 三、根因

1. 同一篇文章从两条路径进入 `data/latest-24h.json`：站点自身 feed（直连 url）+ Google News 主题词 query（聚合 url）。
2. `export_qmd.target_path()` 以 **原始 url** 建索引判重 → 两条 url 互不相识，各自落一个文件；文件名撞车时按「同名不同 url 不覆盖」加 `〔mat-xxxxxx〕`（先在 `sanitize_note_names.py` 里被规范成 `【dupN】`）。
3. 抓正文时 `fetch_article()` 会先解码 Google News → 抓到真页面（所以 gnews 那条有正文）；而直连那条在这些站点上抓不到 → 出现"同文两份、一份空壳"。

## 四、建议方案（按风险从低到高，本轮只做①）

| # | 动作 | 风险 | 说明 |
|---|------|------|------|
| ① | **本报告 + 9 个孤儿改名** | 极低 | 报告即本文件；孤儿改名后可被正常双链引用 |
| ② | **存量正文互补（772 组）** | 低 | 把有正文那条的 `## 摘要`/`## 正文` 回填给空壳。**但收益有限**：这 727 条的直连 url 在 Track 2 实测里抓取成功率很高（美国DOE/EPA 100%），重抓即可，不必抄兄弟笔记 |
| ③ | **根治：`export_qmd` 写 Google News 条目时先解码** | 中 | 解码后的 url 若已在索引中 → **upsert 进既有笔记**（不改 url/id、不新建文件）。需先跑 `--limit` 小批验证不误合并，并复验 `verify_graph.py` |
| ④ | 目录级合并（两条并一条） | **高，不建议** | 合并必须删掉一条 → `url` 字段只能留一个 → 被删那条的 `mat/<sha1(url)>` id 从图谱消失，`related` 引用会断；收益（少一个节点）远小于风险 |

**红线（任何方案都适用）**：不得改写 `url` 字段（`id = mat/<sha1(url)[:12]>` 会漂移、`related` 全断）；收工必须 `python -X utf8 scripts/verify_graph.py` 断链/缺 id/id 重复/孤立全 0 + `python -X utf8 scripts/audit_vault_portable.py Notes/素材库` 全 0。

## 五、与 Track 2（正文缺口）的关系

- 本批 257 个"双空"组 + 727 个"direct 侧空壳"合计约 1241 条无正文笔记，**已包含在** Track 2 的 3858 条 Google News 缺口统计口径之外（它们是 direct url，不在 `--gnews-only` 范围内）→ 全量补抓时建议**不加 `--gnews-only`**，或分两轮：先 gnews 后 direct。
- 两者不要混做：Track 2 补正文（不动结构），本报告治重复（动入库逻辑）。
