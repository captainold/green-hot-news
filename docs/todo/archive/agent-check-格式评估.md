## 三、YAML 合法性

| 检查项 | 结果 |
|---|---|
| 全量严格解析（yaml.safe_load） | **1234/1235 合法（99.92%）** |
| 随机抽样 20 个复核 | **20/20 合法（100%）** |
| 失败案例 | 1 个 |

**失败案例（唯一）**：
- 文件：`2026-08-16 欧盟ETS拟2029扩展航空至EEA外5000公里航班,与CORSIA管辖重\x8f.qmd`
- 问题：`unacceptable character #x008f: special characters are not allowed`
- 根因：爬取时编码损坏（mojibake），title 字段尾部混入 C1 控制字符 U+008F（原文疑似"重叠"的第二个字损坏）；**同一控制字符也出现在文件名中**。
- 影响：该文件被所有严格 YAML 解析器（Obsidian 属性面板、Quarto、脚本）拒绝读取，且按文件名排序时位于异常位置。

**其他格式隐患**（不报错但值得注意）：
- `enabling_tech: [能源]` 等无引号裸词列表 33 处（YAML 合法，解析后值一致，但源格式不统一）；
- 空列表 `[]` 与空字符串 `""` 混用（enabling_tech 用 `[]`，tech_feature 用 `""`），统计口径需注意。

### 6.2 富文本 Markdown

- ✅ 正文是标准 Markdown（`#`/`##`/`###` 标题、`>` 引用、`[链接]`、表格、图片）→ **Quarto 可正常渲染**（.qmd 是 Quarto 原生格式），GitHub 也能预览；
- ⚠️ 正文内 `---` 残留会被渲染为水平分割线（89 个文件）；
- ⚠️ 17 处 base64 data URI 图片：Obsidian **不支持** data URI 图片渲染（Quarto 支持），会显示为空白；
- ⚠️ 14 处 `./W02026...`、`images/xxx/main.svg` 相对路径图片未下载到 attachments/ → 两端都挂图；
- ⚠️ 少数文件正文顶部有 `--- # Introduction` 这类 HTML 残留（`---` 会被解析为 setext 标题或 hr）；
- ⚠️ 文件名 91 字符 + Windows 路径，个别接近 260 字符路径上限，Obsidian 同步/移动端易出问题。

## 七、格式优缺点总结

### 优点
1. **YAML 质量极高**：99.92% 合法率，21 字段全覆盖写入，无引号/特殊字符事故（除 1 个 mojibake）；
2. **多维标签设计专业**：映射国际权威分类（EU Taxonomy/ISIC/GICS/IPC），词典封闭（topics 22 值、enabling_tech 7 值），非自造标签体系；
3. **结构统一**：标题/链接/来源行/三节结构 100% 或高比例统一，机器可解析性强；
4. **文件名规范基础好**：100% 日期前缀、无 Windows 非法字符；
5. **图片本地化策略正确**（attachments/ md5 命名），已完成约一半。

### 缺点
1. **标签填充率失衡**：核心差异化字段（trl 16.4%、ipc 12.7%、people 0.8%、tech_feature 5.5%）标注几乎失效，"多维"实际只靠 layer/isic/enabling_tech/topics 四维撑起；
2. **富文本覆盖率不足**：摘要 42%、技术特征 12.6%，202 个文件无正文节；
3. **重复抓取严重**：76 组跨日重名（约 12% 文件重复），去重失效；
4. **文件名超长普遍**：27.1% 超 80 字符，逼近平台路径限制；
5. **`.qmd` 扩展名与 Obsidian 生态冲突**：Obsidian 默认不识别，属性面板/Dataview 全部落空（需改 .md 或装插件）；
6. **图片引用三套体系并存**（URL/attachments/坏引用），31 处必然挂图。

## 八、最关键 3 个格式问题

1. **`.qmd` 扩展名导致 Obsidian 默认不识别整个数据库** —— 多维标签和富文本设计得再好，Obsidian 属性面板/Dataview 全用不上。这是"Obsidian 兼容性"命题下最根本的冲突，需决策：改名 `.md`（Obsidian 原生，Quarto 需改配置）或保留 `.qmd`（Quarto 原生，Obsidian 需插件/配置），二者必居其一。

2. **标签填充率失衡，多维检索名不副实** —— trl（16.4%）、ipc（12.7%）、people（0.8%）、tech_feature（5.5%）四个字段基本空置，"TRL×专利分类""人物动态""技术护城河"类交叉查询全部落空；且绿色政策维度 tech_feature 恒为 0%。标注环节需补强（或明确降级这些维度）。

3. **76 组跨日重名 = 去重失效 + 约 12% 重复数据** —— 同一文章被重复抓取入库（如 ForestBench 出现 2023-11-28 与 2026-08-17 两版），文件名按日期前缀区分导致重名检测形同虚设；加上 1 个含控制字符的 mojibake 文件名/标题，共 152+ 个文件需要清洗。建议入库前按 url 去重、清洗控制字符、截断超长标题。
