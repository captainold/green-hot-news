## 一、决策记录（待老温拍板）

1. **数据源：FRED 免费 CSV 端点（fredgraph.csv），零成本零 key**（已验证）
   - `https://fred.stlouisfed.org/graph/fredgraph.csv?id=<SERIES_ID>` 单序列直抓 CSV，多序列返回 zip 包（按频率拆文件）
   - 无需 API key、无需注册，符合项目「官方权威 + 零成本」路线（同 X 平台 SSR 直抓思路）
   - 已实测 30+ 指标 ID 全部 200，样例数据正确（见第三节）
   - ⚠️ CRB 综合指数在 FRED 无对应 ID（TRJCRBTT/TRCRB 均 404）→ 用 WTI/布伦特/铜/天然气 4 个代表性商品代替
2. **抓取频率：独立脚本每日 1 次**（不并入 update_news.py 的 30 分钟循环）
   - 经济指标多为日/周/月频发布，每日抓取足够；与新闻 30 分钟节奏解耦，互不拖累
   - 服务器加独立 systemd timer（每日 08:30 跑），本地手动可跑
3. **存储：`data/econ-indicators.json` 时序累积**（每次追加最新值，保留历史全量）
   - 与新闻数据流（history.json/latest-24h.json）完全独立，不打乱现有结构
4. **前端：index.html 新增「📊 经济指标」区域**（关系图谱之后），echarts 折线图按四层分组
   - 已有 echarts.min.js，无需新依赖
5. **范围：一期做美国/全球指标**（沃什框架本身就是美国视角，FRED 全覆盖）；中国对应指标（PPI/社融/LPR/PMI 等）作为二期选项，**待老温决策是否要**
6. **PDFP（国内私人最终购买）FRED 无直接序列** → 用「PCEC96（实际消费）+ GPDIC1（实际私人投资）」合成近似（即国内私人最终购买定义本身），标记为合成指标

## 四、架构设计

```
新增 scripts/fetch_econ_indicators.py（独立脚本，~300 行）
  ├─ ECON_INDICATORS: 指标清单（ID/名称/层级/频率/单位/说明）
  ├─ fetch_fred(session, series_id) → 抓 fredgraph.csv（带 cosd 近 3 年）
  ├─ 更新 data/econ-indicators.json：{ generated_at, series: { [id]: { meta, history: [[date, value], ...] } } }
  └─ 幂等：已有历史保留，仅追加最新值；失败单指标跳过不阻塞

前端 index.html
  └─ 新增 <section class="board board-econ">（关系图谱之后）
     ├─ 每层一个分组标题 + 指标卡网格（最新值/环比/趋势 mini 图）
     └─ 点击指标卡 → 大图 echarts 折线（近 1 年/3 年切换）

部署（服务器 /opt/green-hot-news/）
  └─ systemd timer: green-econ.timer 每日 08:30 跑 fetch_econ_indicators.py
     （与 green-policy.timer 30 分钟互不干扰）
```
