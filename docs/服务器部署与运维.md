## WSL 操作服务器（2026-08-14 沉淀，2026-08-19 修正）

**核心事实**：
1. **WSL ssh/scp 直连可用（2026-08-19 实测）**：`moltbot260130.pem` 在 `/mnt/c` 挂载下权限是 0444/0777，OpenSSH 报 `Permissions too open` 拒绝——**复制到 WSL 原生路径 + chmod 600 即可直连**：`cp /mnt/c/Users/wenyu/.ssh/moltbot260130.pem /root/.ssh/ && chmod 600 /root/.ssh/moltbot260130.pem`。本会话全程用 WSL ssh/scp 完成部署（避开 cmd.exe 引号坑）
2. `sg-moltbot` 别名只在 Windows 的 `~/.ssh/config`，WSL 里没有 → WSL 下用 `ssh -i /root/.ssh/moltbot260130.pem root@47.82.211.111`
3. `/opt/green-hot-news` **不是 git 仓库**——代码同步靠 **scp 推送**，不拉 GitHub
4. 本机 DNS fake-ip 劫持：一律用 IP `47.82.211.111`，不用域名 ywm.life

**模板 0：WSL 直连（agent 首选，2026-08-19 实测）**

```bash
# 一次性准备：复制密钥到 WSL 原生路径（/mnt/c 挂载的密钥权限会被 OpenSSH 拒绝）
cp /mnt/c/Users/wenyu/.ssh/moltbot260130.pem /root/.ssh/ && chmod 600 /root/.ssh/moltbot260130.pem

# 远程命令（无引号嵌套问题）
ssh -i /root/.ssh/moltbot260130.pem root@47.82.211.111 "cd /opt/green-hot-news && .venv/bin/python -m py_compile scripts/update_news.py && echo OK"

# scp 传文件
scp -i /root/.ssh/moltbot260130.pem scripts/update_news.py root@47.82.211.111:/opt/green-hot-news/scripts/update_news.py

# 手动触发一次抓取（oneshot 服务会阻塞等待，nohup 后台化）
ssh -i /root/.ssh/moltbot260130.pem root@47.82.211.111 "nohup systemctl start green-policy.service > /tmp/ghn_restart.log 2>&1 & echo TRIGGERED"
```

**模板 3：复杂命令 / scp 传文件 → 写 .bat 到项目根目录再执行**

> ⚠️ **.bat 必须纯 ASCII**（无中文注释/中文 echo）！write_file 写的是 UTF-8，cmd 按 GBK 解析中文行会乱码并连累后续所有行（报 `'""' 不是命令`）。中文说明写在 bash 命令里，.bat 内容纯英文。

```bat
@echo off
set KEY=C:/Users/wenyu/.ssh/moltbot260130.pem
set SSH=C:/Windows/System32/OpenSSH/ssh.exe
set SCP=C:/Windows/System32/OpenSSH/scp.exe
set REMOTE=root@47.82.211.111
"%SSH%" -i %KEY% -o IdentitiesOnly=yes %REMOTE% "cd /opt/green-hot-news && .venv/bin/python -c \"import ast; ast.parse(open('scripts/update_news.py').read()); print('syntax OK')\""
"%SCP%" -i %KEY% -o IdentitiesOnly=yes C:\Users\wenyu\Documents\Obsidian_wen\green-hot-news\scripts\update_news.py %REMOTE%:/opt/green-hot-news/scripts/update_news.py
"%SSH%" -i %KEY% -o IdentitiesOnly=yes %REMOTE% "md5sum /opt/green-hot-news/scripts/update_news.py"
```

**代码同步流程**：本地改脚本 → scp 上传 → 服务器语法检查 → 测试运行（`--output-dir /tmp/gpn-test` 不碰生产）→ systemd timer 每 30 分钟自动用新脚本跑（无需重启）。

### 多终端并行开发纪律（2026-08-19，与 AGENTS.md 一致）

老温会同时开多个终端写不同功能。**不用分支隔离**（同一工作目录下 `git checkout` 会重写工作区文件互相踩踏；独立 clone 又太重）。三层纪律：

1. **提交纪律**：commit 前 `git diff HEAD --stat` 确认改动范围；只 add 自己负责的文件；update_news.py 单文件多人改用 `git add -p` 挑自己的 hunk，**不把别人的半成品带进自己的 commit**
2. **区域约定**：update_news.py 按功能区域切（fetch 函数区 / BUILTIN_SOURCES / SOURCE_SCORE / SITE_LAYOUT / 关键词区 / 白名单组），并行会话各写各的区域冲突最小
3. **部署纪律**：谁收尾谁 scp；scp 前 md5 对比确认同步方向；部署前 `py_compile` + 确认 BUILTIN_SOURCES 注册无悬空引用（防半成品崩服务器 timer）。实例：2026-08-19 另一终端 290 行"国际智库/投行"半成品被整文件 scp+commit 带上——好在代码完整未崩，但应避免

**踩坑速查**：WSL ssh 直连 ✓（密钥复制到 /root/.ssh + chmod 600，见模板 0；旧说法"WSL 连不上"已过时，2026-08-19 实测）| `/c/...` 路径 ✗（git sh 不认）| cmd 单行塞复杂命令 ✗（引号嵌套炸）| cmd 单行单引号 ✗（cmd 不认单引号）| cmd 单行转义双引号 ✗（三层转义失真）| **.bat 含中文 ✗（UTF-8 被按 GBK 解析，乱码连累全文件）** | 服务器 `git pull` ✗（非 git 仓库）| `ssh sg-moltbot`（WSL）✗（别名在 Windows）| 域名 ✗（fake-ip 劫持）。判断标准：WSL 直连优先，cmd.exe/.bat 仅 Windows 侧（Obsidian Git 插件）场景用。

## 双向同步竞态修复（2026-08-14，素材层 git）

**现象**：服务器 systemd 日志偶发 `green-policy.service: Failed with result 'exit-code'`，抓取成功但 git push 报 non-fast-forward 被拒 → set -e 下整个服务 FAILURE。根因：服务器每 30 分钟 push 素材库 + 本地 Obsidian 插件每 30 分钟 autoPush，两边都基于旧 base 提交；且旧 sync.sh **只在有新提交时 push、从不 pull**，服务器工作区与远程越走越远。

**修复（sync.sh 素材层段 v2）**：
1. 无论有无本地提交，先 `git pull --rebase -X theirs origin master` —— 整合本地 Obsidian 已推送的提交
2. `-X theirs` 关键：索引文件（ai-index.md / 媒体库.md / 政策库.md）两端都会重写，冲突**必然发生**，自动取远程（本地 Obsidian）版本，rebase 不中断；服务器新笔记正常重放
3. push 失败只提示（下周期自动重试），**不在失败分支里嵌套 pull**（会二次触发 rebase 卡死）
4. 服务器 Notes 仓库配置了**仓库级** user.name/user.email（green-policy-bot）——rebase 重放提交需要 committer identity，旧脚本只用了命令级 `-c` 配置，rebase 不认，直接 fatal

**踩坑记录**：
- rebase 需要 committer identity：`git -C Notes config user.name green-policy-bot && git -C Notes config user.email bot@ywm.life`
- 历史积压（39 个未推送提交）用 `git pull --rebase -X theirs` 一次性重放成功
- 误操作提交清理用 `git rebase --skip`（内容全弃）而非 reset --hard（老温禁止）
- **WSL git 看 Notes 状态全是 M（行尾符幻觉）**：WSL git autocrlf=false 对比 CRLF 工作区 vs LF blob 永远显示修改；**必须以 Windows git（cmd.exe 模板）为准**（Obsidian 插件同环境）
- rebase 切换分支时未跟踪文件与目标树同名会阻塞（"could not detach HEAD"）：先把冲突的未跟踪文件 mv 到 /tmp 备份，rebase 完成后再判断恢复
