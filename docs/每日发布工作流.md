# 每日发布工作流（公众号 + 小红书）

> 2026-09-23 建立。半自动：脚本精选+生成素材，人工过目后一键发布。
> 代码：`scripts/publish/`（独立区域，与 update_news.py 主流程解耦，只读 latest-24h.json）

## 流程总览

```
data/latest-24h.json（77源×30min 服务器抓取+六维打分）
        │
        ▼ select_daily.py     精选引擎（A线≥70、三层配额、去重、防重复推送）
digest.json
        ├─▶ render_cards.py   小红书卡片（Chrome headless HTML→PNG，1080×1440）
        ├─▶ build_xhs.py      小红书文案（标题≤20字+正文≤1000字+话题标签）
        └─▶ build_wechat.py   公众号图文 markdown（可选官方API传草稿箱）
        │
        ▼ daily_publish.py    总入口（一键全流程 + 生成 publish-checklist.md）
data/publish/<date>/
```

## 每日操作（3 分钟）

```bash
# 1. 生成当日全部素材（--refresh 先本地刷新数据兜底，服务器正常时可省）
python scripts/publish/daily_publish.py --all --refresh

# 2. 人工过目 data/publish/<今天>/ 下的 digest.json、xhs/*.png、两平台文案

# 3. 发布（见产物内 publish-checklist.md 详细指引）：
#    小红书 App：按序上传 xhs/ 图片 + 粘贴 xhs-post.md
#    公众号后台：粘贴 wechat-article.md（或 --draft 直传草稿箱）

# 4. 发布完成后登记，防明日重复推送
python scripts/publish/mark_published.py
```

## 一次性配置（可选）

- **公众号草稿箱直传**：建 `scripts/publish/config.local.json`（已 gitignore）：
  ```json
  { "wechat": { "appid": "wx...", "appsecret": "..." } }
  ```
  之后 `daily_publish.py --all --draft` 自动存草稿箱（IP 需在公众号后台白名单内）。
- **精选参数**：`scripts/publish/config.json` → `selection`（A线分数/条数/每源配额/时效）。

## 定时调度

- 本会话 schedule 提醒每日 **08:35** 触发，agent 自动跑全流程并报告头条（会话关闭则不触发；
  每日执行后自动接力排下一天）。
- 数据由服务器 30 分钟 timer 持续刷新，本地 `--refresh` 仅兜底。

## 设计约束（与项目标准对齐）

- **不打分**：只消费 `score/score_level/dimension/sub_dimension` 字段（打分唯一权威 =
  `docs/标准文档/打分体系标准.md` v5.0，本工作流不引入新公式）。
- **三层分组**：政策/创新/产业 + 七细类标签，与雷达站一致。
- **防重复**：`data/publish/state.json` 记录已发布 URL 指纹（保留最近 3000 条）。
- **隐私**：`data/publish/` 与 `config.local.json` 已加入 .gitignore（产物含当日新闻清单，密钥绝不入库）。

## 已知边界

- 小红书无官方 API，发布走 App 手动（浏览器自动化有风控风险，不做全自动）。
- Chrome headless 渲染在受限沙箱内会因 crashpad 自终止 → 需完整权限跑 `render_cards.py`。
- 公众号 API 存草稿是官方接口，但**群发仍需人工在后台点击**（半自动边界，防止误发）。
